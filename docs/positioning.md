# TriBot 的差异点，以及能拿数字证明的部分

> 所有 TriBot 数字都来自本仓库的实测脚本 `scripts/bench-context.ts`（`pnpm bench`），
> 输入是本仓库的真实文件、真实 Bot 配置（`data/tribot.db`）和真实工具 Schema。
> 竞品数字来自公开资料，逐条标了来源；查不到的写「未公开」，不编。

## 一句话

**别人在把 agent 做得更全能，TriBot 在把 agent 做得更便宜、更可控、更能被审计。**

## 三个「别人没有」的硬差异

### 1. 峰谷 + 订阅额度感知的路由（唯一）

别人是「选一个模型用完」；TriBot 每次请求前先算：

1. GLM / MiniMax 订阅额度还有没有剩 → 有就用，**边际成本 ¥0**
2. 没有 → DeepSeek，且**看当前是峰还是谷**（工作日 9–12 / 14–18 是峰，其余半价）

算例（1M 输入 tokens）：

| 路径 | 成本 |
|---|---|
| 订阅额度内（已付费） | ¥0 |
| DeepSeek 峰时 | ¥0.50 |
| DeepSeek 谷时 | ¥0.25 |

一个月 50M tokens 的差别是 **¥12.5–25**，而任务结果完全一样。这笔钱别人赚不到，是因为他们只有一家供应商。

### 2. 上下文三道闸：不只是省钱，是「不爆窗」

实测（cl100k）：

| 场景 | 全量 | TriBot 处理后 | 省 |
|---|---:|---:|---:|
| 读 3523 行 lockfile | 56.2k | 1.1k | **98.1%** |
| 命令输出 2.2MB 打包产物 | 615.3k | 626 | **99.9%** |
| 40 条历史压缩 | 12.7k | 5.2k | **58.8%** |
| 30 轮 + 3 次大输出 + 6 次重复调用 | 849.4k | 99.3k | **88.3%** |

为什么这比「便宜」更重要：任何 200K 窗口的 agent，一次 `cat` 2.2MB 都会直接失败或触发强制压缩、丢掉前面的上下文。TriBot 的处理是**原文落盘 + 给模型一个 `expand_output(id)` 的把手**——既不爆窗，也不丢信息。

这就是 DSH 的 `dsh-spill` 和 Claude Code 的截断思路，但 TriBot 把它做成了**用户可见的账本**（上下文洞察里的「压缩省下 N 次 / X tokens」），而不是藏在日志里。

### 3. 计划模式的「硬门禁」

DSH 的 `dsh-plan-mode` 明确说：**不限制工具**，靠沙箱和审批兜底。TriBot 的选择是反过来的——计划模式下 `write_file` / `run_command` / `http_fetch` 直接返回错误：

```
计划模式：先提交计划，用户批准后再写文件
```

差别在于**失败成本**：一次误写要回滚、要重新读文件、要重新建立上下文；按 88.3% 的压缩比算，回滚一次 5k tokens 的误写，实际浪费的是 5k + 重读 5k + 重试的推理 tokens。硬门禁把这类浪费变成 0。

## 为什么「前缀 733 vs 12,200」要谨慎看

诚实说：Claude Code 的 9,400 token 工具描述**换来了更强的泛化能力**，它的工具能覆盖更多边缘场景。TriBot 只有 5–9 个工具、按 Bot 白名单裁剪，前缀自然小。

所以正确的说法不是「我们更强」，而是：

- **短任务、高频任务**（本地文件、脚本、定时巡检）：固定开销小 16 倍，单次更划算
- **开放性、长尾任务**：Claude Code 的工具覆盖更好

这也决定了 TriBot 该做什么：**别去卷通用能力，去卷「本地、高频、要审计」的场景**。

## 还能做什么（按性价比排序）

| 想法 | 为什么别人做不了 | 预期收益 | 工作量 |
|---|---|---|---|
| **峰谷 Routine 调度**：定时任务自动排到 DeepSeek 谷时（23:00–08:00 + 周末） | 单供应商做不到「换时间换价格」 | 按量任务成本直接 **-50%** | S |
| **会话预算墙**：给每个会话设 ¥ 上限，超了自动降档或停 | 订阅制产品没有「花多少钱」的概念 | 把「省 token」变成可管理的钱；可出日报/月报 | M |
| **答案投票**：同题对比跑 3 家，自动比对分歧点、给共识结论 | 别人只有一家模型 | 质量差异化；成本只在主动开启时 3× | M |
| **技能自动沉淀**：一次成功任务 → 一键存成 SKILL.md | DSH 有技能，但没有「从会话里蒸馏」 | 复用率提升，长任务 token 下降 | M |

## 口径与局限

- token 用 `gpt-tokenizer`（cl100k_base）统一计；GLM / DeepSeek 自家 tokenizer 通常低 5–15%，所以**绝对数会偏高，比例基本不变**
- 前缀缓存按 DeepSeek 公开的「命中按输入价 10%」估算；实际折扣随官方调价变化
- 竞品数字来自公开文章与官方文档（链接见上），**不是我们跑出来的**；未公开的写「未公开」
- 综合场景是构造的（30 轮 + 3 次大输出 + 6 次重复），不是真实用户日志；真实分布会更分散
